# Product Requirement Document (PRD)

**Projeto:** Combustivel_APP (Flutter)
**Objetivo:** Migração de Persistência Local (`shared_preferences`) para Nuvem (`Supabase`/PostgreSQL)
**Status:** Pronto para Desenvolvimento

---

## 1. Resumo Executivo
O aplicativo **Combustivel_APP** realiza o controle de gastos veiculares. A atual persistência de dados ocorre localmente através do pacote `shared_preferences`. O escopo deste PRD abrange a substituição completa da camada de armazenamento local pela plataforma **Supabase**, utilizando o banco de dados PostgreSQL. A estrutura de domínio do Flutter (classes `Veiculo` e `Abastecimento`) já está consolidada e servirá de base estrita para a modelagem do banco de dados, minimizando impactos na interface gráfica (UI).

---

## 2. Arquitetura de Dados (Modelagem Supabase)
O agente ou desenvolvedor deve provisionar as seguintes tabelas no PostgreSQL. A tipagem das colunas foi desenhada para manter paridade exata com os métodos `fromMap` e `toMap` já existentes no projeto Dart.

### Tabela: `veiculo`
| Coluna | Tipo PostgreSQL | Restrições | Mapeamento Dart |
| :--- | :--- | :--- | :--- |
| `id` | `integer` | `PRIMARY KEY`, `GENERATED BY DEFAULT AS IDENTITY` | `int? id` |
| `nome` | `text` | `NOT NULL` | `String nome` |
| `modelo` | `text` | `NOT NULL` | `String modelo` |
| `placa` | `text` | `NOT NULL` | `String placa` |
| `ano` | `text` | `NOT NULL` | `String ano` |

### Tabela: `abastecimento`
| Coluna | Tipo PostgreSQL | Restrições | Mapeamento Dart |
| :--- | :--- | :--- | :--- |
| `id` | `integer` | `PRIMARY KEY`, `GENERATED BY DEFAULT AS IDENTITY` | `int? id` |
| `veiculoId` | `integer` | `FOREIGN KEY` (referência `veiculo.id`) | `int veiculoId` |
| `nomeVeiculo` | `text` | `NOT NULL` | `String nomeVeiculo` |
| `posto` | `text` | `NOT NULL` | `String posto` |
| `tipoCombustivel`| `text` | `NOT NULL` | `String tipoCombustivel` |
| `litros` | `numeric` | `NOT NULL` | `double litros` |
| `valorPorLitro` | `numeric` | `NOT NULL` | `double valorPorLitro` |
| `kmAtual` | `numeric` | `NOT NULL` | `double kmAtual` |
| `kmAnterior` | `numeric` | `NULL` | `double? kmAnterior` |
| `data` | `text` | `NOT NULL` | `String data` |

> ⚠️ **Aviso de Domínio:** Os atributos `valorTotal` e `mediaConsumo` pertencentes à classe `Abastecimento` são variáveis computadas (getters) em tempo de execução no Dart. **Não** devem ser provisionados como colunas no banco de dados.

## 3. Plano de Execução (Tarefas do Agente)

### Fase 1: Setup de Infraestrutura
1. Inserir pacote `supabase_flutter` nas dependências do `pubspec.yaml`.
2. Implementar a inicialização `Supabase.initialize()` no método `main()` do arquivo `main.dart`.

### Fase 2: Camada de Repositório (Data Layer)
1. Construir a classe `SupabaseRepository` para abstrair a comunicação com a API do Supabase.
2. Implementar os métodos CRUD para a entidade **Veículo**:
   - `inserirVeiculo(Veiculo veiculo)`
   - `listarVeiculos()`
   - `deletarVeiculo(int id)`
3. Implementar os métodos CRUD para a entidade **Abastecimento**:
   - `inserirAbastecimento(Abastecimento abastecimento)`
   - `listarAbastecimentos()`
   - `deletarAbastecimento(int id)`

### Fase 3: Refatoração da Camada de Apresentação (UI/State)
1. Rastrear todos os arquivos responsáveis pelo estado da aplicação que importam ou utilizam `shared_preferences`.
2. Substituir a injeção/chamada do `shared_preferences` pelo novo `SupabaseRepository`.
3. Ajustar as funções de interface para lidar com operações assíncronas de rede (`Future`, `async/await`), garantindo feedback visual (ex: `CircularProgressIndicator`) durante o carregamento dos dados.

---

## 4. Requisitos Não Funcionais e Restrições Técnicas

- **Segurança (RLS):** Durante esta fase de migração, configurar o banco com Políticas de Segurança em Nível de Linha (Row Level Security) **desabilitadas** ou em modo permissivo (Allow All) para facilitar os testes de integração.
- **Segurança de Tipagem:** A conversão de tipos monetários/decimais retornados pelo Supabase deve continuar passando pelo casting de segurança existente (`(map['litros'] as num).toDouble()`) para evitar exceções do tipo *TypeError* caso a API retorne um `int` no lugar de um `double`.
- **Preservação de Código:** O agente não deve alterar as regras de negócio nos métodos `mediaConsumo` e `valorTotal`.

---

## 5. Critérios de Aceite (DoD - Definition of Done)

- [ ] Dependência do `shared_preferences` foi totalmente removida do `pubspec.yaml` e do código-fonte (onde for aplicável aos dados de domínio).
- [ ] A compilação do aplicativo ocorre sem erros em ambiente de desenvolvimento.
- [ ] O fluxo de inserção de um novo veículo ou abastecimento reflete instantaneamente no banco de dados do Supabase.
- [ ] Fechar e reabrir o aplicativo recupera os dados de consumo e veículos a partir da nuvem com sucesso, preenchendo corretamente as listas na interface gráfica.
